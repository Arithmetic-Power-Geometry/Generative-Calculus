# GC-II Audit 118 — Dynamic-Signature Compilation and Fresh-Name Collision

## Question

Can GC-II escape the static local-to-global/CSP collision by allowing capability creation to change the *type/signature of future compatibility constraints*?

## Result

**Decisive falsification for every bounded finite signature universe.**

Changing the currently active type/action signature does not create a new operational invariant when every type/action that may ever appear belongs to a fixed finite universe. The active signature can be reified as ordinary machine state, producing a fixed-signature transition system with exactly the same labelled histories.

This kills the natural finite-world version of the post-Audit-117 proposal.

---

## 1. Dynamic-signature machine

Let

- `Q` be a finite control-state set,
- `A` be a finite universe of possible action/type symbols,
- `S ⊆ A` be the signature currently active,
- `z = (q,S)` be a configuration,
- `δ(q,S,a) = (q',S')` be defined only when `a ∈ S`.

The system may therefore create or delete currently usable actions/types by changing `S` after every transition.

Let `Hist_h(z)` be the set of action-labelled histories of length at most `h` beginning at `z`.

## 2. Fixed-signature compilation

Construct an ordinary labelled transition system

`C(M) = (Q × 2^A, A, ->)`

with fixed alphabet `A`, where

`(q,S) -a-> (q',S')`

iff

`a ∈ S` and `δ(q,S,a) = (q',S')`.

The apparent signature change has disappeared: `S` is now simply part of state.

### Theorem 118.1 — Bounded Dynamic-Signature Compilation

For every finite dynamic-signature machine `M`, every configuration `z`, every finite horizon `h`,

`Hist_h^M(z) = Hist_h^{C(M)}(z)`.

More strongly, the identity relation on configurations is a labelled transition-system isomorphism between the operational graph generated by the dynamic-signature presentation and the compiled graph.

### Proof

For any configuration `(q,S)` and action `a`, the dynamic machine permits `a` exactly when `a ∈ S`; by construction the compiled machine has exactly the same `a`-labelled edge and the same successor. Hence the one-step transition relations coincide on the common configuration set. Equality of all finite histories follows immediately by induction on horizon. QED.

### Consequence

No quantity that depends only on finite operational histories/reachability can distinguish `M` from this compilation. Therefore

`signature change alone != representation-independent capability creation`.

Any positive GC-II residual must depend on an independently justified realization restriction that *forbids* this reification or assigns it a non-removable physical/operational burden.

## 4. Prior-art collision

The remaining escape would be to permit genuinely unbounded/fresh symbols rather than selection from a fixed finite universe. That move is not automatically novel either.

### Dynamic interfaces / mobile channels

Channel mobility explicitly treats a process interface as dynamic: receiving a channel can extend the interface available to the process. This is established mobile-process semantics, not a new GC-II mechanism.

Gerard Ekembe Ngondi, "Denotational semantics of channel mobility in UTP-CSP," *Formal Aspects of Computing* 33 (2021):
https://link.springer.com/article/10.1007/s00165-021-00546-3

### Fresh names and changing communication structure

The pi-calculus already uses a countably infinite set of names, passes names between processes, and models changing connectivity/interaction capabilities. Fresh-name/channel creation and mobility therefore occupy mature semantic territory.

Sangiorgi & Walker, *The Pi-Calculus: A Theory of Mobile Processes* (Cambridge University Press; online chapter edition 2025):
https://www.cambridge.org/core/books/picalculus/processes/0438521AE8630A9B19A5A489DF838638

A recent systems-modeling summary likewise describes pi-calculus as representing processes with changing structures and newly created connections:
https://link.springer.com/chapter/10.1007/978-3-032-06901-6_2

### Dynamic runtime types / graph transformation

Graph-transformation semantics already admit runtime type graphs enriched with dynamic node/edge types and dynamic constraints, showing that changing runtime type structure is also established formal-method territory:
https://link.springer.com/article/10.1007/s10270-018-00706-9

### State-reification perspective

Abstract State Machines represent algorithmic configurations as mathematical structures over a fixed finite vocabulary, with transitions updating state. This reinforces the general compilation lesson: a changing operational object can often be represented as data/state in a sufficiently expressive fixed vocabulary.

ASM background and fixed-vocabulary postulate discussion:
https://link.springer.com/book/10.1007/3-540-44518-8
https://link.springer.com/article/10.1007/s13194-020-00337-2

## 6. What survives

The route that survives this audit is narrower:

> Find an independently meaningful realization boundary under which converting *schema/type creation into ordinary state data is not operationally free*, and prove a quotient-stable lower bound on the extra realization burden.

A valid next candidate must satisfy all of the following.

1. The boundary is specified independently of the desired theorem; it cannot be chosen post hoc to force a residual.
2. The residual survives optimal encodings/translators allowed by that boundary.
3. It is invariant under harmless renaming/refactoring of the internal representation.
4. It cannot be reduced to communication complexity, memory complexity, query/oracle complexity, program-size complexity, mobile-process freshness, nominal automata, graph transformation, or ordinary resource conversion.
5. A finite or computable witness family must show a nonzero lower bound after all admissible reifications are optimized.

Until such a restriction is found and justified, *signature creation* should not be used as the breakthrough claim for GC-II.
